## Compute decision

The candidate learner code uses sklearn logistic and ridge estimators; the existing synthetic evaluator and exact allocator also run on CPU. No frozen GPU-capable challenger or measured GPU speedup exists. Enabling Kaggle GPU would consume a scarcer resource without changing the evidence. The local machine has about 16 GB physical RAM; the full Lenta frame has 549,867 development rows and many numeric features, with nested cross-fitting. The complete full-development run has **not** been profiled to completion, so we do not claim a measured laptop memory or time limit. It is queued as a Kaggle CPU extension with the same fixed source, seeds, candidate pool, cap, and development-only role boundary. If the Kaggle runtime fails, keep its failure manifest and narrow the next resource decision from the observed limit.

## Portable run and acceptance

The [Kaggle kit](../kaggle/README.md) contains a private-upload ZIP builder, pinned numerical package versions, the verified project wheel, a runnable notebook, and a final-manifest wrapper. The raw inputs are included **only in the local ZIP artifact**, not committed source. The builder verifies raw and wheel SHA-256; the Notebook rechecks all inputs; the runner checks installed core-source SHA-256 and writes status, environment, split IDs, features, actual completion time, and result hashes. A [local full-Lenta preflight](../reports/v4/full_lenta_preflight_20261002/RUN_MANIFEST.json) completed in 23.61 seconds without indexing outcomes: 549,867 development rows, 137,162 held-back confirmation rows, 191 feature columns, and development-ID SHA-256 `f5d392917ee0aa133c9449b20599a688377efb30a93b38867fc507f0f4e3c9bc`. Kaggle's [Notebook documentation](https://www.kaggle.com/docs/notebooks) supports Dataset inputs, CPU/GPU settings, package installation, and `/kaggle/working` output; its [Dataset documentation](https://www.kaggle.com/docs/datasets) supports private ZIP-backed inputs.

Accept a returned full-Lenta run only if the manifest is `COMPLETE`, the raw/source hashes match this kit, `n_development` is 549,867, confirmation labels were not indexed, all three outer folds have complete candidate results, the recorded result SHA-256 matches the downloaded JSON, and the Kaggle notebook log/version is retained. Compare to the archived 60k development estimate as a **sensitivity**, with no claim of independent replication or measured telecom value. Do not overwrite the 60k artifact.
