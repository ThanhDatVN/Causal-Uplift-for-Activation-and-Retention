# R1 follow-up design after failed transfer

**Planning document, 30 September 2026. No follow-up results exist.** The completed [R1 transfer](../reports/v4/next_evaluator_transfer/TRANSFER_REPORT.md) is a development diagnosis for this follow-up. It cannot be relabeled as independent confirmation. Any method selected using its T1–T6 results must be frozen before a new generator, seeds, and outcomes are opened.

## Failure to explain

| Design | Observed candidate coverage | Declared requirement | Working hypothesis |
|---|---:|---:|---|
| T2, rare fixed rule | Selected paired DR interval 0.882; normal paired DR reference 0.941 | Wilson lower bound at least 0.92 | The selected skewness correction can become anti-conservative in a different rare-event law. Do not apply it universally. |
| T3, batch sharp null | Percentile reallocation bootstrap 0.907 | Same coverage floor and null false-promotion ceiling | Rank boundary changes and skewed DR scores are not captured adequately by this percentile interval. |

These are hypotheses from inspected outcomes, not validated explanations.

## Bounded development work

1. Audit each method's estimand and influence contribution algebraically. Keep a fixed-rule population contrast separate from a future-batch capped-policy contrast; preserve no-contact as the comparator. Confirm oracle truth with an independent calculation and track Monte Carlo error.
2. Implement three **candidate families**, each with one prespecified recipe before follow-up validation: (a) ordinary paired DR normal interval for independent fixed rules; (b) customer-level studentized reallocation bootstrap for capped independent batches; (c) the same reallocation scheme with whole-customer clusters. The current percentile bootstrap and selected skewness-adjusted interval remain references. Use development simulations only to choose numerical stabilization and bootstrap count; report every variant tried.
3. Build a clean broken-control fixture for clusters: assign at customer level, use a strong shared pre-treatment customer shock in both outcomes, keep the policy and 20% cap on unique customers, and compare only the resampling unit. The invalid row-IID interval should either fail known-truth coverage at a predeclared scale or be explicitly labeled an ineffective control. Separately verify that a policy feature contract rejects evaluation-outcome columns, and that a real assignment log is required to detect false declared propensities.
4. Freeze one candidate per supported design class, its source and dependency hashes, cell matrix, generator family, all seed namespaces, 2,000 worlds per cell, and Wilson acceptance gates **before** unseen validation. Keep old T1–T6 seeds and all observed outcomes out of the validation set. Publish failed cells, interval exceptions, and null promotions, not only aggregate means.

## Decision rule

For each supported cell require the 95% Wilson lower bound on empirical 95% coverage to be at least 0.92; sharp-null cells also require the 95% Wilson upper bound on positive-lower-bound promotion to be at most 0.05. Require the oracle-truth Monte Carlo standard error to be at most one tenth of the median interval half-width. A failed cell narrows the licensed design scope; it cannot be removed after inspection. Passing synthetic validation would license only the implemented synthetic estimand/design combination. It would **not** establish a real telecom treatment effect, a partner pilot, or a business launch.

CPU is sufficient for the current tabular generators. Profile training-side iterations before freezing compute, then run one complete validation. Prepare Kaggle inputs only if a specific candidate exceeds the local budget; keep the same seeds, data roles, protocol, and output schema.

## Implementation amendment, frozen before new validation (2 October 2026)

The new producer is `src/telco_churn/r1_repair.py`. It uses a new six-cell generator with `X1 ~ Bernoulli(0.4)`, `X2 ~ Bernoulli(0.3)`, bounded `Z ~ Uniform(-1,1)`, a different baseline event law, and a new seed namespace (`884211`). These choices differ from the inspected T1–T6 worlds. `X1 + 0.05 Z` ranks every `X1=1` ahead of every `X1=0`, so future-batch top-20% truth is an exact binomial expectation; fixed-rule truth is analytic. There is no truth Monte Carlo error. Each validation cell uses 2,000 independent worlds and 2,000 customers; clustered cells have two records per customer, with assignment at customer level and a common pre-treatment uniform outcome shock shared with probability 0.90.

The six cells are F1 fixed/null with `e=.85`, F2 fixed/rare heterogeneous with variable `e`, B1 independent capped-batch/null with `e=.85`, B2 independent capped-batch/rare heterogeneous with variable `e`, C1 clustered capped-batch/null with `e=.5`, and C2 clustered capped-batch/heterogeneous with `e=.5`. Fixed cells use the production paired DR **normal** interval. Batch cells use 299 whole-customer bootstrap draws, reallocate the cap within each draw, and form a studentized interval from the selected whole-cohort contribution variance. A standard-error floor of `max(1e-12, 0.01 × original SE)` is fixed in source. The old skewness-adjusted fixed interval and a percentile interval from the *same* batch bootstrap draws are descriptive references, never selected by the validation outcomes. This is a candidate design, not a theoretical guarantee for the non-smooth capped policy. [Dudík, Langford, and Li](https://arxiv.org/abs/1103.4601) motivate the doubly robust score; [De Angelis, Hall, and Young](https://www.math.wustl.edu/~kuffner/AlastairYoung/DeAngelisHallYoung1993a.pdf) show that ordinary bootstrap interval accuracy can be delicate for non-smooth quantile functionals. Their result is background, not a proof about this allocator.

For the cluster broken control, the previous row bootstrap also changed decision units. The replacement keeps one frozen top-20% **customer** decision set and the same point estimate, then compares customer-level and deliberately invalid row-IID normal standard errors. This variance-only control isolates the dependence error; it does not by itself validate the reallocation bootstrap. It is discriminating only if the customer's coverage Wilson lower bound reaches 0.92 and the invalid row interval's coverage Wilson upper bound is below 0.92; otherwise it is explicitly inconclusive and the full synthetic gate does not pass. The earlier harness [already rejected](../reports/v4/next_evaluator_transfer/NEGATIVE_CONTROL_INTERPRETATION.md) an outcome-derived rank and a claimed propensity inconsistent with a known generator log. A real campaign still needs an external assignment log; no statistical test can prove a self-declared propensity is the actual randomization probability.

The `dry-run` command writes source/config/environment hashes before any new validation outcome is drawn. The validation command refuses changed source or an existing result. Every failed interval counts against coverage; the six declared cells remain in the denominator. The gate is unchanged: the 95% Wilson lower bound for 95% coverage must reach 0.92 in every cell, and each sharp-null cell's positive-lower-bound Wilson upper bound must be at most 0.05. Passing only licenses this synthetic design region. A separate development run, if needed to profile performance, must use a different seed and output directory and cannot be pooled with the frozen validation.

**Safety reference added after the first 100-world development profile, before validation freeze:** the initial studentized candidate undercovered badly (batch coverage 0.60–0.92 across four cells; fixed F1 normal 0.78). We retain it as the declared candidate and expose a conservative bounded-difference interval as a separate reference. With logged action probabilities bounded below by `e_min`, oracle DR action difference has absolute value at most `M = 1 + 1/e_min`; replacing one independent customer changes a fixed-rule or reallocated top-K batch estimator by at most `2M/n`. A two-sided 95% McDiarmid radius is therefore `M sqrt(2 log(40)/n)` around the observed estimator. This is valid only under the generator's independent-customer, pre-treatment ranking, correct propensity, and oracle-nuisance conditions. It is expected to be too wide for a decision; the predeclared practical precision check is a half-width no larger than **one conversion per 1,000 eligible customers**. Coverage without usable precision will be reported as such, not promoted. See [McDiarmid's original bounded-differences chapter](https://www.cambridge.org/core/books/abs/surveys-in-combinatorics-1989/on-the-method-of-bounded-differences/AABA597B562BDA7D89C6077E302694FB) for the concentration inequality; the project-specific `2M/n` sensitivity argument is derived above.
